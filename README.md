# 康师傅 · 聚会游戏

Flutter 聚会游戏 App，支持 iOS、Android，包含 26 款已接入对局的游戏。

用户下载网站位于 [`website/`](website/README.md)，使用独立 Flutter Web 项目实现。构建后可将 `website/build/web/` 内的文件放入 1Panel 静态网站目录，Android 下载按钮始终指向最新 GitHub Release。

人数按各游戏分别设置；**谁是卧底至少 1 名主持人 + 3 名玩家，五子棋和反应力对决恰好 2 人**。

## 怎么玩

- 选游戏 → 同机开局 → 填写朋友昵称 → 开始，公开操作与私密传手机回合自动切换。
- 选游戏 → 创建联机房间 → 分享六位房间码 → 每人加入并准备 → 房主开始。
- 团队游戏按座位交替分橙队、蓝队，每队至少两人；谁是卧底由房主担任独立主持人，拥有上帝视角，其余玩家随机分配平民与卧底。
- 口述、动作、哼歌类游戏需要在场互动或自己的语音通话；App 提供题目、计时、计分及轮次控制。

## 运行

```sh
flutter pub get
flutter run
```

联机地址由构建配置 `PARTY_HUB_WS` 注入；源码默认指向本机测试地址。正式发布由 GitHub Actions Secret 提供 WSS 地址。服务端代码、部署文件和生产配置不在公开仓库中。同机游戏无需服务端。

```sh
flutter run --dart-define=PARTY_HUB_WS=wss://example.invalid/ws
```

## 当前边界

已实现 26 款首版对局；不是所有经典桌游的全部扩展规则。具体玩法在 App 游戏详情页查看。

房间保存在服务内存，重启服务会清空；会话令牌只在 App 内存中，杀进程不能恢复旧座位。断网后可在 App 内自动重连。没有内置语音、历史战绩或题库 OTA 服务。Android 已接入 GitHub Release 更新代码和签名发布工作流，实际发行与真机覆盖安装需另行验证；iOS 暂未接入更新。正式上架前仍需确认应用标识、渠道签名，并进行 Android/iOS 多人真机测试。

## Android 更新发布

推送与 `pubspec.yaml` 版本一致的 tag（例如 `v1.0.0+1`）触发 GitHub Actions：检查、测试、签名构建 APK，发布到 [GitHub Releases](https://github.com/Aniu456/party_hub/releases)。正式版启动后自动检查更新，用户中心可手动检查；确认下载后校验文件并交给系统安装。iOS 暂不接入。

签名配置、版本规则和发行步骤见 [Android 发布说明](docs/android-releases.md)。

## 用户中心与交互优化（2026-09-28）

大厅右上角进入用户中心，只设置昵称，无需账号密码。昵称通过 `SharedPreferencesAsync` 保存在本机；创建、加入房间以及同机第一位会自动填写。在开局页第一次填写或修改本人昵称也会保存。保存失败明确提示并保留原值，不把昵称作为联机认证凭证；既有房间继续使用入局时的名字。

本轮还增加人数筛选与筛选重置，搜索时收起介绍区域；准备房间在正常竖屏下固定操作区，分别显示缺人、离线、未准备和同步状态；倒计时增加进度条，结算突出最终结果，画板清空增加确认并避免跨回合清除新画作。

本轮 56 项相关测试已通过（复用未变化的有效检查）：昵称读写与失败处理、入口自动填写、人数筛选、准备与离线状态、画板确认、26 款对局首屏和响应式布局。昵称恢复目前为存储模型测试证据；加入原生存储插件后，需要重新运行模拟器应用，才能验收实际重启后的昵称保留。


## 三套设计参考落地（2026-09-28）

主要页面现以 Quizzo 公开预览的白底分区、蓝色主操作和圆角卡片为设计方向，结合 Nucleus UI Lite 的组件层级与 Game UX Kit 的游戏交互参考，并实际打包 Open Peeps 的 93 张 CC0 人物插画（49 半身、30 站姿、14 坐姿），服装统一使用 App 蓝色。蓝白主题统一大厅、详情、房间和用户中心；小头像裁切放大，游戏内采用圆环倒计时、编号选项和分队比分面板。26 款游戏玩法与权限保持原实现。

本轮静态检查和 56 项相关测试通过，已检查浅色/深色及主要页面组件渲染图；尚未完成这版 UI 的模拟器或真机验收。来源、授权范围、接入方式及预览见 [设计来源记录](docs/design_sources.md)。
